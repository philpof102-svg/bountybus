# Example run — Hathor Network wallet bounty (2026-08)

A real bountybus run, kept because an honest example of a **clean target** is more useful than a
cherry-picked catch. Program: Hathor Network on Immunefi (max $20k; impacts: execute arbitrary
system commands, direct theft of funds, direct theft of NFTs; PoC + KYC required).

## Preflight

- **Scope**: 4 in-scope repos, all JS/TS wallets — `hathor-wallet-lib` (shared core),
  `hathor-wallet-headless` (HTTP API server), `hathor-wallet` (Electron), `hathor-wallet-mobile`
  (React Native). Only RCE / theft-of-funds / theft-of-NFTs pay.
- **Version match**: cloned `master` HEAD of each; matched the current releases
  (headless 0.41, lib >4.1, desktop 0.35, mobile 0.39). ✓
- **Dedup**: 0 published GitHub security advisories on any of the four. ✓
- **PoC harness**: both core repos ship a Docker **privatenet** integration harness
  (`__tests__/integration/`), so a PoC can run end-to-end off mainnet. ✓

## Hunt

6 finders, scope-locked, one per surface: headless auth/RCE · atomic-swap & partial-tx theft ·
wallet-lib untrusted tx/script deserialization · wallet-lib signing/UTXO/amount handling ·
nano-contracts · Electron/React-Native client RCE & seed exposure.

## Result: 0 payable findings

Every candidate died on scope or reachability, not on hand-waving. The near-misses, kept honest:

| Observation | Real defect? | Why it is NOT payable |
|---|---|---|
| API key compared with `!==` (not constant-time) in `api-key-auth.middleware.js` | Yes, a hardening gap | A network timing attack on the key is not demonstrable → "theoretical without PoC" is out of scope |
| Dynamic `import(filename)` for plugins in `plugins/child.js` | Works as designed | Plugin name comes from the operator **config file**, not any request → needs privileged access |
| `partialTxProposal.signData()` signs the wallet's inputs after checking only balance + input validity — never that the wallet *receives* value | Works as designed | Signing requires the victim to call their **own authenticated API** with the proposal; the counterparty has no API key. Signing a bad deal is operator responsibility / normal workflow → out of scope |

## Takeaway

Mature codebase, bounty live since 2023, no advisories — the shallow bugs are gone, and what remains
needs either privileged access or the victim's deliberate cooperation. **Zero is the correct answer
here.** Reporting any of the three near-misses as "critical" would have been marketing, not a bug.
